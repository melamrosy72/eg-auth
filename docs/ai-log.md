### Decisions
- argon2 is wrapped in an injectable `PasswordHasher` (requested by the user) so unit tests replace it through DI; ESM namespace exports are read-only and can't be spied on. A separate unit test runs the real `PasswordHasher` and checks the `$argon2id$` prefix.
- Duplicate email: `UsersService.create` inserts directly and maps Mongo error `11000` to `ConflictException('Email is already registered')` only when `keyPattern.email` is set; any other duplicate key error is rethrown (500). No pre-check. The `AuthService` unit test uses the real `UsersService` with a mocked model so the mapping is covered.
- DTO messages: each field's `@IsString` carries that field's first rule message, and every other rule passes for non-strings. Reason: Nest's `ValidationPipe` flattens every failed constraint without de-duplicating, so a missing field would otherwise report every rule (including the max-length one). `ValidationPipe({ stopAtFirstError: true })` was evaluated as a replacement (review note 1) with a throwaway comparison test (deleted) that ran every DTO case from the unit and e2e tests through both approaches. It changed messages in 5 cases, so the current approach was kept: (a) passwords failing several rules return only one message (`abcdefgh` loses `...at least one number`; `aaaaaaa` loses two of three); (b) class-validator evaluates decorators bottom-up, so with the plain `@IsString/@MinLength/@MaxLength` order a missing name returned `Name must be at most 50 characters`, a missing signup password `...special character`, and a missing signin password `...at most 128 characters`. Reordering the decorators would fix (b) but not (a), because `stopAtFirstError` returns one message per property by design.
- Signup password length uses `PASSWORD_RULES.length` as the check; the message (min vs max) is chosen by the code-point count. Signin password: non-empty, max 128 code points, no policy.
- Name length uses `.length` (UTF-16 units): `specs/04` §1 requires code points only for passwords, and this matches Zod's default `.min()`/`.max()` on the client.
- `AuthService.signup`/`signin` return `{ user, tokens }`; the controller sets cookies via `setAuthCookies`. `clearAuthCookies` (same `cookieOptions()` helper) is written and unit-tested now, used in Phase 3.
- `JwtAccessStrategy` loads the user on every protected request so `/me` returns 401 for a deleted user. `UsersService.findById` returns `null` for a non-ObjectId `sub` instead of a `CastError` 500.
- `/me` 401 uses Nest's default `Unauthorized` message (Phase 0 decision).
