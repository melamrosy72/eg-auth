### Decisions
- React Router: `react-router@7.18.4`, imported from `react-router` (the v7 package exports `BrowserRouter`, `MemoryRouter`, `Routes`, `Route`, `Navigate`, `Link`; `react-router-dom` is not installed). npm 11 chose 7.18.4 over `latest` 8.4.0 because 8.4.0 has `engines.node >=22.22.0` and the local Node is 22.16.0. Same reason for `jsdom@29.1.1` instead of 30.1.3 (`^22.22.2 || …`). The user approved keeping v7 and jsdom 29 in review: v8 needs Node ≥ 22.22 and has no feature this project needs. Declarative `<Routes>` mode, so Phase 6 tests can wrap `AppRoutes` in `MemoryRouter`.
- shadcn defaults: `--defaults` gives the `base-nova` style on Base UI (`@base-ui/react`), not Radix; kept because `specs/05` §1 asks for the default theme.
- `cn` package: shadcn's registry generates `src/lib/utils.ts` as `export { cn } from "cn"` whatever the CLI version, so pinning the CLI alone didn't help. Re-running init with `shadcn@4.21.5` produced the same file. The registry items `https://ui.shadcn.com/r/styles/{base-nova,new-york-v4,radix-nova}/utils.json` all have `content: export { cn } from "cn"` and list the unversioned dependency `cn`, so the CLI installs the latest version (0.5.0). Following a supply-chain minimum-age policy, `cn` is pinned exactly to `0.4.0` (published 2026-09-22, 25 days old). Inspected first: maintainer `shadcn <m@shadcn.com>`, published by GitHub Actions OIDC with SLSA provenance (the same publisher as `shadcn@4.21.5`), no dependencies (self-contained, not a wrapper around clsx/tailwind-merge), and only `build`/`compile-tables` scripts (no install hooks). `src/lib/utils.test.ts` checks `cn('p-2', 'p-4') === 'p-4'` and that falsy values are dropped (`'a c'`). Recorded in the README under Security decisions.
- `shadcn` is pinned exactly to `4.21.5` in `devDependencies` (the CLI put `^4.22.0` in `dependencies`): the app only imports `shadcn/tailwind.css`, which is resolved at build time. The CLI itself still bundles `cn@0.2.6` (published 2026-09-06) through its own `^0.2.4` range; it is a dev-only, transitive copy. `npm audit` reports 7 high findings (`braces` via `fast-glob`, `ts-morph`, `@shadcn/registry`), all inside the shadcn CLI; `npm audit --omit=dev` → 0.
- Lockfile: the first `shadcn init` (4.22.0) installed with the system npm 10.9.2, which left 0 `libc` fields, so the lockfile was regenerated with `npx npm@11 install` → 26. The user then upgraded the global npm to 11.21.1; after the re-init with 4.21.5 and the exact pins, the lockfile still has 26 `libc` fields.
- `utils.test.ts` puts the falsy value in a `boolean` variable rather than writing `false && 'b'`: the literal triggers oxlint's `no-constant-binary-expression` warning. The test checks the same thing.
- `NotFoundPage` uses `<Link className={buttonVariants()}>`, not `<Button nativeButton={false} render={<Link />}>`: with the latter Base UI sets `role="button"` on the `<a>` (found by the test), so screen readers don't announce it as a link.
- `.oxlintrc.json`: `react/only-export-components` is off for `src/components/ui/**`, because the generated `button.tsx` exports `buttonVariants`; generated files are not edited.
- `ApiError` normalisation (`specs/05` §5) is left for Phase 5 with the interceptor; the Phase 4 scope is the bare instance.
- `client/.gitignore` from create-vite kept; it doesn't un-ignore `.env` files.
